LLM API 概念：streaming、tool calling、context window、reasoning

约 12 分钟 · 用 PI 的真实类型定义解释 · 目标：读懂 PI 给模型发了什么、模型回了什么

这一课结束你会得到：用 PI 代码里的真实类型说清：一次 LLM 请求包含哪些部分（system prompt + messages + tools），响应为什么是流式的，tool calling 怎么工作，reasoning 是什么。

1. 一次 LLM 请求长什么样

PI 给模型的请求体由 Context 描述（PI/packages/ai/src/types.ts）：

export interface Context {
  systemPrompt?: string;   // 系统提示词：定义 agent 的角色与规则
  messages: Message[];     // 对话历史：user / assistant / toolResult 交替
  tools?: Tool[];          // 可调用的工具清单（模型可以选择调用）
}

加上 Model（选哪个模型、它的参数）和鉴权信息，就构成一次完整请求。PI 在 agent-loop.ts 的 streamAssistantResponse 里组装它：

const llmContext: Context = {
  systemPrompt: context.systemPrompt,
  messages: llmMessages,
  tools: context.tools,
};

2. Streaming：为什么回复是"流"出来的

LLM 生成一个回答要几千甚至几万 token，一次性返回会让用户盯着空白等几十秒。主流做法是 streaming：模型每生成一个（或一小段）token 就立刻推送，客户端逐字渲染。

在 PI 里，响应被翻译成 AssistantMessageEvent 事件流，常见类型：

事件含义
start响应开始，创建 partial 消息
text_delta新生成的文本片段（打字机效果的来源）
thinking_delta模型的内部推理过程（reasoning 模式）
toolcall_delta模型决定调用工具，参数在流式拼装
done响应结束，result() 拿到完整消息

agent-loop 用 for await 逐条消费，每来一个 text_delta 就广播 message_update，TUI 立刻把新文字画上去。

3. Tool Calling：模型怎么"动手"

光说话不够，agent 要能读文件、跑命令。Tool calling 是 LLM 提供的机制：

  1. 你在请求里附上 tools 清单（每个工具含 name、description、参数的 JSON schema）
  2. 模型判断需要动手时，不直接输出文字，而是输出一个 toolCall：{ name, arguments }
  3. 你的代码执行这个工具，把结果作为 toolResult 消息发回
  4. 模型看到结果，继续生成回答或再调下一个工具

PI 里这个循环就在 agent-loop.ts：抽出 message.content.filter(c => c.type === "toolCall")，执行，把结果 push 回上下文，再调一次模型。tool calling 是 agent 能"做事"的核心机制。

4. Context Window：模型能记住多少

每个模型有一个 context window（上下文窗口）——一次请求里 system prompt + 历史消息 + 工具定义 + 输出 加起来不能超过的 token 上限。PI 的 Model 类型里有：

contextWindow: number;   // 输入+输出总 token 上限
maxTokens: number;       // 单次输出 token 上限

当对话越来越长，总 token 逼近窗口上限时，PI 会触发 compaction（压缩）：把早期对话总结成一段摘要替换掉，腾出空间。这就是 transformContext 钩子做的事。

第 2 课提到过的细节：如果模型输出被 token 上限截断（stopReason === "length"），PI 会让该轮所有 tool call 直接失败——因为截断的 JSON 参数可能不完整，执行有风险。

5. Reasoning：模型的"思考过程"

一些模型（如 o1、Claude thinking）支持 reasoning——在给出最终答案前，先输出一段内部推理（不直接作为回答）。PI 用 thinkingLevel 控制强度：

export type ThinkingLevel = "minimal" | "low" | "medium" | "high" | "xhigh" | "max";

开启后，模型响应里会出现 thinking_delta 事件（推理文本），与 text_delta（最终回答）分开。PI 把推理过程单独渲染，让用户看到模型"在想什么"。推理也消耗 token，所以 PI 有 thinkingBudgets 来限制每轮推理的 token 量，避免推理把整个输出额度吃光。
