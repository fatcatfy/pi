Node.js 事件与 Stream：PI 怎么流动数据

约 12 分钟 · 锚定 EventStream 与 EventEmitter 真实实现 · 目标：理解"事件"和"流"两种数据传递方式，以及 PI 为什么两种都用

这一课结束你会得到：区分"事件总线（广播）"和"流（有序消费）"；看懂 PI 的 EventStream.push() / for await 机制；知道 SSE 是什么。

1. 两种数据传递：事件 vs 流

PI 里有两种"异步传数据"的方式，别混淆：

事件（EventEmitter）流（Stream / EventStream）
比喻广播站：对所有听众广播水管：数据按顺序流到消费端
消费者可有多个订阅者，互不干扰通常一个消费者，按顺序拿
PI 用途TUI 内部组件通信模型响应、Agent 事件流

2. 事件：EventEmitter 的 emit / on

PI 的 event-bus.ts 是最简封装：

import { EventEmitter } from "node:events";

const emitter = new EventEmitter();
return {
  emit: (channel, data) => emitter.emit(channel, data),
  on: (channel, handler) => {
    const safeHandler = (data: unknown) => { try { handler(data); } catch {} };
    emitter.on(channel, safeHandler);
    return () => emitter.off(channel, safeHandler);
  },
};

三个核心操作：

  • emit(channel, data)：在某个频道上发消息，所有订阅该频道的 handler 都会被调用
  • on(channel, handler)：订阅频道，返回一个取消订阅函数（PI 用 try/catch 包裹 handler，防止一个组件崩了带垮整个总线）
  • off(channel, handler)：取消订阅

事件适合"多个地方都关心同一件事"——比如用户切换模型时，好几个 UI 组件都要刷新。

3. 流：PI 自己实现的 EventStream

模型的流式响应不能用事件——它有顺序（token 必须按到达顺序处理），且通常只有一个消费者。PI 写了一个 EventStream 类（PI/packages/ai/src/utils/event-stream.ts）：

export class EventStream<T, R = T> implements AsyncIterable<T> {
  private queue: T[] = [];
  private waiting: ((value: IteratorResult<T>) => void)[] = [];
  private done = false;

  push(event: T): void {
    const waiter = this.waiting.shift();
    if (waiter) {
      waiter({ value: event, done: false });   // 有人在等，直接给
    } else {
      this.queue.push(event);                  // 没人等，先排队
    }
  }

  async *[Symbol.asyncIterator]() {            // 让 for await 能用
    while (true) {
      if (this.queue.length > 0) yield this.queue.shift()!;
      else if (this.done) return;
      else {
        const result = await new Promise(r => this.waiting.push(r));  // 挂起等下一个
        if (result.done) return;
        yield result.value;
      }
    }
  }
}

这是一个生产者-消费者模型：

  • 生产者（模型响应处理代码）调 stream.push(event) 往里塞数据
  • 消费者（agent-loop）用 for await (const event of stream) 逐条取
  • 如果消费者还没准备好，数据先进 queue；如果队列空了，消费者挂起（waiting），等下一次 push

这就是上一课 for await (const event of response) 背后的真实机制。

4. SSE：LLM 响应为什么是"流"

大模型供应商的 API 默认支持 Server-Sent Events（SSE）——服务器一边生成 token 一边通过 HTTP 连接推送，每个 token 是一个 data: {...}\n\n 格式的事件。PI 的供应商适配器（如 api/openai-responses.ts）解析这些 SSE chunk，每解析到一个就 stream.push({ type: "text_delta", partial: ... })，于是 agent-loop 能逐 token 渲染。

一句话：SSE 是网络层的流，EventStream 是 PI 进程内的流。适配器把 SSE 翻译成 EventStream 事件。

5. Node 内置流（简介）

除了自定义 EventStream，PI 还用 Node 内置流：TUI 从 process.stdin（可读流）读用户按键，写屏到 process.stdout（可写流）。这些在理解 TUI 渲染时才会深入，前置阶段知道"stdin 是流、stdout 是流"即可。
