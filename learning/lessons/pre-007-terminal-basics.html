终端基础：PI 的 TUI 怎么画屏、怎么读键

约 8 分钟 · 建立"终端是什么"的心智模型 · 目标：理解 PI TUI 渲染和键盘输入的底层机制

这一课结束你会得到：知道终端里的文字是"字符+转义序列"画出来的，raw mode 让按键不用回车就生效，stdin/stdout 是两个流。

1. 终端本质：字符流 + 控制序列

终端（terminal）不是画布，它只接收一个字符流。要让文字变颜色、移动光标、清屏，靠的是 ANSI 转义序列——一串以 \x1b[（ESC + [）开头的特殊字符，终端看到后执行对应动作，不显示出来。

序列作用
\x1b[31m后续文字变红
\x1b[0m重置所有样式
\x1b[2J清屏
\x1b[H光标移到左上角
\x1b[10;5H光标移到第 10 行第 5 列

PI 的 TUI（packages/tui）就是计算每一帧该输出哪些字符和哪些转义序列，写到 stdout 上。所谓"差分渲染"就是：只输出相对上一帧变化了的部分，减少写入量、让刷新更顺滑。

2. stdin / stdout：两个独立的流

每个终端程序有三个标准流：

  • stdin（标准输入）：键盘输入进来的地方，PI 的 TUI 从这里读按键
  • stdout（标准输出）：程序正常输出，PI 把画面写在这里
  • stderr（标准错误）：错误信息

它们都是流（见第 3 课），PI 的 TUI 订阅 stdin 的 data 事件拿到按键，把渲染结果写入 stdout。

3. Raw Mode：按键即时响应的秘密

默认终端处于 cooked mode：你打的字先存在缓冲区，按回车才一起发给程序（这就是为什么普通 CLI 程序要回车才执行）。

交互式 TUI 需要每按一个键就立刻响应（方向键、Esc、单键快捷键），所以 PI 会把终端切到 raw mode：

  • 按键直接发给程序，不缓冲、不回显
  • 程序自己决定怎么处理（比如把 j 解释成下移）
  • 退出时必须切回 cooked mode，否则终端会"坏掉"（打字看不到、回车不执行）

这也是为什么 TUI 程序崩溃后有时终端会乱——恢复逻辑没跑完。PI 的 TUI 有清理逻辑保证退出时恢复。

4. PI 中相关的代码位置

  • packages/tui：终端渲染库（差分渲染、ANSI 输出）
  • packages/coding-agent/src/modes/interactive/：交互模式，从 stdin 读键、渲染聊天界面

读这部分代码时，遇到 process.stdin.setRawMode(true)、\x1b[、process.stdout.write 就不陌生了。
