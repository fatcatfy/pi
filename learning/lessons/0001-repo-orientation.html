Lesson 1 / Series: pi 架构入门

仓库地图：pi 是什么、它怎么分层、从哪里读起

约 10 分钟 · 面向 TS/Node 初学者 · 目标：脑子里装下一张仓库地图

这一课结束你会得到：① 一张三层结构的仓库地图；② 三个"先读这里"的入口文件；③ 以后遇到任何名词（session、tool、provider…）都知道去哪个包找答案。

1. 一句话：pi 是什么

pi（Pi Agent Harness）是一个极简的终端 AI 编程代理。你在项目目录里敲 pi，它启动一个交互式终端界面（TUI），由大语言模型驱动，能读文件、改文件、跑命令，把一轮轮的对话组织成可保存、可恢复、可分支的 session（会话）。核心刻意保持小，靠 TypeScript 扩展、skills、prompt 模板和主题来扩展。

它是"产品"的那部分叫 coding-agent；在它下面还垫了两层库（运行时、基础），这三层构成本仓库的全部。（依据：仓库 README 与 PI/packages/coding-agent/docs/index.md）

2. 三层地图

  • ③ 基础层是一批小库：ai 把 OpenAI / Anthropic / Google 等各家 LLM 供应商统一成一个 API；tui 是终端渲染库；telemetry 是遥测契约；chord 是服务 + RPC + 复制状态的基础运行时；protocol / client / server 是客户端与服务端之间的 JSONL RPC 三件套；session-backends/sqlite-node 负责把会话存进 SQLite。
  • ② 运行时层只有 agent 一个包：与具体模型、具体界面无关的 agent 运行时——主循环（调模型 → 决定调工具 → 拿到结果 → 继续），以及工具调用与会话状态管理。
  • ① 应用层只有 coding-agent 一个包：你敲的 pi 在这里。它负责 TUI、CLI、内置工具（读/写/跑命令）、会话管理和扩展加载——是唯一有"产品形态"的包。

另有 evals（跑 benchmark 的评估包）不在主链路上，理解架构时可以先跳过。

3. 包一览表

包（目录）一句话职责学习顺序
PI/packages/coding-agent交互式编程代理 CLI（pi 命令）第一站（产品面）
PI/packages/agentagent 运行时：主循环、工具调用、会话状态第二站（核心）
PI/packages/ai统一多家 LLM 供应商 API第三站（核心）
PI/packages/session-backends/sqlite-node会话持久化（SQLite）后续
PI/packages/protocol · client · serverJSONL RPC 三件套后续
PI/packages/chord服务 + RPC + 复制状态基础运行时后续
PI/packages/tui终端 UI 渲染库（差分渲染）后续
PI/packages/telemetry遥测契约与参考实现后续
PI/packages/evalsbenchmark / 评估测试暂跳过

真实的构建顺序也等于理解顺序（来自根 package.json 的 build 脚本）：

chord → tui → telemetry → ai → agent → session-backends/sqlite-node
→ protocol → client → server → coding-agent

越靠左越"底"，越靠右越接近用户。读代码时顺着这条链从下往上走，依赖最干净。

4. 三个"先读这里"

  1. PI/packages/coding-agent/src/cli.ts（入口）—— package.json 里 "bin": {"pi": "dist/bundle/cli.js"}，源码入口就在 src/cli.ts。想追"敲下 pi 之后发生了什么"就从这里开始。
  2. PI/packages/agent/src/agent-loop.ts（主循环）—— 想理解"agent 是怎么转起来的"，读它。下一课我们会全程走一遍。
  3. PI/packages/coding-agent/docs/index.md（文档索引）—— 26+ 篇文档的总入口。建议顺序：index → quickstart → sessions → extensions。
别踩的坑：PI/packages/ai/src/models.generated.ts 是一个由脚本生成的超大文件（各家模型的元数据目录），仓库规则明确禁止手改。第一遍读代码时不要从它开始，会被淹没。

5. 一条建议的读库路径

  1. 先读文档建立手感：docs/index.md + quickstart.md（现在）。
  2. 把它跑起来：按根 README 的 Development 命令本地构建，再用 ./pi-test.sh 启动。
  3. 自顶向下追一次会话：coding-agent → agent → ai（下一课一起走一遍"一次输入怎么变成一次模型调用"）。
  4. 任何不清楚的地方，随时向老师（本 agent）提问——每课末尾都欢迎 follow-up。
