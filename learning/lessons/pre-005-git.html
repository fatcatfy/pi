Git：读 PI 代码必备的命令

约 8 分钟 · 重点是 PI 仓库实际会用到的操作 · 目标：能独立 clone、看分支、看 diff、看提交历史

这一课结束你会得到：会用 6 个命令解决读 PI 代码时 90% 的 Git 需求，并知道 PI 的 AGENTS.md 里有哪些不能踩的 Git 红线。

1. 读代码时最常用的 6 条命令

命令用途在 PI 里的典型用法
git clone <url>克隆仓库到本地git clone https://github.com/earendil-works/pi
git branch -a看所有分支（本地+远程）确认当前在哪个分支，有哪些特性分支
git log --oneline -n 20看最近 20 条提交了解最近在改什么、谁在改
git show <commit>看某次提交改了什么理解一个功能是怎么加进来的
git diff <file>看工作区某文件相对版本库的改动确认自己改了哪些行
git status看当前工作区状态哪些文件改了、哪些暂存了

2. 三个核心概念

  • 工作区：你正在编辑的文件
  • 暂存区：git add 后、git commit 前的中间状态
  • 版本库：已提交的历史（.git 目录）

提交流程：编辑 → git add 文件 → git commit -m "描述"。

3. PI 仓库的 Git 红线（来自 AGENTS.md）

PI 是多人协作仓库，AGENTS.md 明确禁止以下操作（会毁掉别人的工作）：

  • git reset --hard / git checkout . / git clean -fd / git stash —— 会丢失未提交修改
  • git add -A / git add . —— 会把别人的改动一起提交，必须 git add 具体路径
  • git commit --no-verify —— 绕过检查
  • 不要 force push

这些规则对人和 agent 一视同仁。读代码阶段你暂时只会用到 clone / log / diff，不会碰到这些红线，但知道它们存在很重要。
