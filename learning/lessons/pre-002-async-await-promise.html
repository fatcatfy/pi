async/await 与 Promise：读懂 Agent Loop 的异步骨架

约 12 分钟 · 全部来自 packages/agent/src/agent-loop.ts 真实代码 · 目标：能顺着异步调用链追踪一次模型调用

这一课结束你会得到：看懂 async function、await、for await、Promise.all、AbortSignal——这些正是 Agent Loop 转起来的全部异步机制。

1. 为什么 PI 全是 async

PI 要做的事几乎都不能同步完成：发 HTTP 请求等模型、读写文件、跑子进程、把事件推给 TUI 渲染。这些操作在等待期间如果阻塞整个程序，界面就卡死了。JavaScript（以及 TypeScript）的解法是：把"等"包装成 Promise，用 async/await 写得像同步代码，但实际不阻塞。

2. 基础：async 函数返回 Promise

任何 async function 的返回值都会被自动包成 Promise。来自 agent-loop.ts：

async function runAgentLoop(
  prompts: AgentMessage[],
  ...
): Promise<AgentMessage[]> {
  ...
  await runLoop(...);
  return newMessages;
}

虽然 return newMessages 看起来返回的是数组，但函数签名声明 Promise<AgentMessage[]>——调用方必须 await 或 .then() 才能拿到真实数组。async 函数里 return 的值，外部一定要 await。

3. await："在这里等一下，但不阻塞"

await emit({ type: "agent_start" });
await emit({ type: "turn_start" });

await 会暂停当前函数的执行，直到右边的 Promise 完成，然后继续。关键：暂停的只是这个函数，不是整个程序——其他代码（比如 TUI 渲染、用户按键）照样跑。这就是为什么 PI 能一边等模型一边显示打字机效果。

4. for await：PI 流式响应的核心

模型响应是流式的——一个 token 一个 token 地返回，不是一次性给完整结果。PI 用 for await 逐条消费：

for await (const event of response) {
  switch (event.type) {
    case "text_delta":
      partialMessage = event.partial;
      await emit({ type: "message_update", message: { ...partialMessage } });
      break;
    case "done":
      const finalMessage = await response.result();
      ...
  }
}

response 是一个异步迭代器（async iterator）。for await 的意思是："每次循环等下一个事件到达，处理它，再等下一个"。模型每吐一个 token，循环就跑一次，把增量广播出去——这就是 TUI 上看到的逐字输出。

记住：for await 处理的是"一系列会在未来到达的值"。普通 for 处理同步数组，for await 处理异步流。

5. Promise.all：并发执行多个工具

当模型一次发起多个工具调用，PI 会并行执行而不是串行等待：

const orderedFinalizedCalls = await Promise.all(
  finalizedCalls.map((entry) =>
    typeof entry === "function" ? entry() : Promise.resolve(entry)
  ),
);

Promise.all([...]) 接收一个 Promise 数组，同时启动它们，等全部完成后返回结果数组（顺序与输入一致）。如果其中任何一个 reject，整个 all 会立刻 reject。这就是为什么多个独立的文件读取可以同时进行、更快返回。

6. AbortSignal：如何取消正在进行的异步操作

用户按 Esc 或切换会话时，PI 需要中断正在等的模型请求或工具执行。机制是 AbortController + AbortSignal：

// agent.ts 里创建
const abortController = new AbortController();
// 传给所有异步调用
await runAgentLoop(..., abortController.signal, ...);

// 取消时
abort(): void {
  this.activeRun?.abortController.abort();
}

信号会一路传到 streamFunction(model, ctx, { signal }) 和 tool.execute(..., signal)。被 abort 的 fetch 会抛 AbortError，工具执行会检查 signal.aborted 提前退出。主循环据此在 stopReason === "aborted" 时收尾。

7. try/catch/finally：异步世界的兜底

try {
  await executor(abortController.signal);
} catch (error) {
  await this.handleRunFailure(error, aborted);
} finally {
  this.finishRun();
}

await 抛错时，用 catch 接住（模型请求失败、工具抛异常都走这里）。finally 无论成功失败都执行——PI 用它清理 activeRun 状态，保证即使出错也不会卡在"正在运行"。
