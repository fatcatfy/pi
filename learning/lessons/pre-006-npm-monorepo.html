npm & Monorepo：PI 的 10+ 包怎么组织

约 8 分钟 · 锚定 PI 的真实 package.json 与 workspaces · 目标：理解为什么 PI 是 monorepo、包之间怎么依赖、怎么构建

这一课结束你会得到：看懂 PI 的 package.json workspaces 字段，知道包之间的依赖方向，会跑构建和检查命令。

1. 什么是 Monorepo

一个 git 仓库里放多个 npm 包，而不是一个包一个仓库。PI 就是典型 monorepo：根目录下 packages/agent、packages/ai、packages/coding-agent 等各自是一个独立的 npm 包，但共享同一个 git 历史、同一套构建工具。

好处：跨包改功能时一次提交就能改完、原子化；依赖的包直接用本地源码，不用发布。

2. workspaces：npm 的 monorepo 机制

PI 用 npm workspaces（不需要 lerna/turborepo）。根 package.json 里：

"workspaces": [
  "packages/*",
  "packages/session-backends/*"
]

这告诉 npm：packages/ 下每个子目录、packages/session-backends/ 下每个子目录都是一个 workspace 包。npm install 时，npm 会把这些本地包用符号链接连到根 node_modules，所以 @earendil-works/pi-agent-core 实际上指向 packages/agent 的源码——改了源码立刻生效，不用重新发布。

3. 包之间的依赖方向（构建顺序）

PI 的构建脚本严格按依赖顺序（第 1 课见过）：

chord → tui → telemetry → ai → agent → session-backends/sqlite-node
→ protocol → client → server → coding-agent

越靠后越依赖前面的。比如 coding-agent 依赖 agent，agent 依赖 ai。所以必须先 build 底层，上层才能编译通过。

4. 常用命令

命令作用
npm install安装所有依赖（含 workspace 符号链接）
npm run build按顺序构建所有包
npm run check类型检查 + lint（PI 改代码后必跑）
npm run dev -w packages/agent只在某个包里跑 dev

-w（workspace）参数让命令只在指定包里执行。排查单个包问题时常用。

5. PI 的依赖安全约定

AGENTS.md 里强调：

  • 直接依赖钉死精确版本（不用 ^、~）
  • 安装时用 --ignore-scripts，不跑第三方包的生命周期脚本（安全）
  • 锁文件 package-lock.json 改动需审查
