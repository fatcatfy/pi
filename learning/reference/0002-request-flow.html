请求数据流速查：一次 prompt 的 10 步

Lesson 2 的压缩速查 · 每一步：做什么 → 在哪

10 步链路

  1. 用户输入——interactive-mode.ts 收下回车文本，调 session.prompt(userInput)
  2. 会话封装——agent-session.ts 第 1108 行调 agent.prompt(messages)，进入 pi-agent-core
  3. 包成消息——agent.ts normalizePromptInput 产出 user AgentMessage：{ role, content: [{type:"text",text}], timestamp }
  4. 启动循环——agent-loop.ts runAgentLoop → runLoop；事件：agent_start / turn_start / message_start
  5. 翻译边界——streamAssistantResponse：transformContext（压缩等）→ convertToLlm（AgentMessage[] → Message[]）→ 组 llmContext{systemPrompt, messages, tools}
  6. 模型调用——streamFunction(model, llmContext, { apiKey, signal })；默认 streamSimple（sdk.ts 安装），provider-composer 按 model.api 路由到供应商适配器，发 HTTP/SSE
  7. 流式事件——for await 处理 start / text|thinking|toolcall _delta / done；partial 消息实时写回上下文并广播 message_update（TUI 流式渲染）
  8. 最终消息——done 时 response.result() 得到完整 assistant 消息；若有 toolCall：校验参数 → beforeToolCall → tool.execute → afterToolCall → 生成 toolResult 消息
  9. 再循环——toolResult 追加进上下文，hasMoreToolCalls=true，回到第 5 步再问一次模型（携带完整历史）
  10. 收尾输出——无 toolCall → turn_end → shouldStopAfterTurn → agent_end(messages) → TUI 渲染最终回复；会话落盘可恢复

两个关键类型

类型是什么活跃范围
AgentMessagepi 内部的对话消息（user / assistant / toolResult）整个 agent 循环
Message传给 LLM 的格式只在 streamFunction 边界（convertToLlm 转换）

事件一览

事件含义
agent_start / agent_end整轮 run 开始 / 结束（agent_end 携带全部新消息）
turn_start / turn_end一轮"问模型"的开始 / 结束（一轮 = 一次模型调用及其工具执行）
message_start / message_update / message_end单条消息的创建 / 流式更新 / 完成
tool_execution_start / _update / _end工具生命周期（含 partial result 流）
