已创建于仓库根目录 .vscode/launch.json，包含两个配置：

  1. Debug Pi Interactive：tsx 运行 src/cli.ts，无参数，集成终端 + 可选 ANTHROPIC_API_KEY

本仓库实际遇到的坑（文档未提）：首次运行会报 ERR_MODULE_NOT_FOUND ... providers/data/.manifest.json——模型目录数据是生成文件，未提交。需先执行：npm --prefix packages/ai run hydrate-model-data（生成各 provider 的 *.json 与 .manifest.json）。

1. 断点链路总览

一次交互输入的完整调用链，从敲下 pi 到模型返回：

cli.ts → main.ts → agent-session-services.ts（组装服务）
       → agent-session-runtime.ts（Runtime）
       → interactive-mode.ts run() → getUserInput()
       → agent-session.ts prompt()
       → agent-loop.ts runAgentLoop → streamAssistantResponse（LLM）
       → executeToolCalls（工具）→ ... 循环
       → 返回渲染

3. 建议的最小实践路径（只打 4 个点）

初学者不必 13 个点全打，这条路径能覆盖"输入→模型→工具"主线，每步都能确认上一课学的链路：

  1. 打 #8（prompt 预处理）→ 看到消息怎么构造、skill 怎么展开
  2. 打 #10（runAgentLoop 入口）→ 跨入核心循环
  3. 打 #11（streamAssistantResponse）→ 看到发给模型的 llmContext，验证第 2 课内容
  4. 打 #12（executeToolCalls）→ 看到工具调用如何被执行（含 beforeToolCall 钩子）
打印模式（-p "..."）不需要 TUI 交互即可走到 #10/#11，适合首次验证断点链路。交互模式（Debug Pi Interactive）适合看 #7 输入与工具真实执行。

6. 本环境实测：CDP 断点链路数据（真实调用 DeepSeek）

沙箱里无法开 VS Code，改用 CDP（Chrome DevTools Protocol）直连 node --inspect-brk 实际跑了一次 pi -p "Summarize this repo" --model deepseek-v4-flash。 tsx/esbuild 会把代码压缩成极少数超长行，按下述方法把断点精确钉到字节列，再逐点恢复执行并求值表达式。完整脚本与日志：learning/.tmp/pi-cdp-trace.mjs、pi-cdp-trace.jsonl。

关键技术点（写进你的断点调试笔记）：esbuild 压缩后的文件只有 3~10 行，V8 的"行断点"会整体落到模块顶部（表现为作用域只有 module/global、所有变量 ReferenceError）。 正确做法：从 Debugger.getScriptSource 里提取内联 base64 sourcemap，用 generatedPositionFor(..., LEAST_UPPER_BOUND) 把源码行+列映射成生成代码精确 line:column，再用该列打断点；断点必须落在函数体内首条语句（打在函数声明行时，参数还没绑定，同样 ReferenceError）。
